功能确认清单（前端逻辑闭环规格）

逐环节确认三种模式的闭环行为；✦ 已修 = 本次代码已落地的断点修复。

模式环节闭环行为（前端 / 后端契约）状态
OIDC 直连
mode: oidc		 登录页探测GET /v1/auth/config → {mode:"oidc", providers:[{id,label}]}；渲染 SSO 按钮 + 本地密码回退（任何模式保留本地登录兜底）已有
发起授权按钮整页跳转 GET /v1/oidc/:id/auth → 302 IdP authorize（state + PKCE S256）；oidc_state httpOnly cookie 绑定浏览器会话已有
回调失败 ✦任意失败（state 不符 / 换码失败 / 无用户名 / 开户失败）→ 302 /login?oidc_error=…；登录页读取参数展示错误条并清理地址栏（原先返回裸 JSON 401，闭环断裂）已修
回调成功验签 ID Token → 提取 preferred_username → groups 命中 admin_groups 即 admin → 自动开户（密码为随机值，不可密码登录）→ Set-Cookie: dockge_token（httpOnly）→ 302 /已有
会话建立SPA boot() → GET /v1/me（同源 fetch 自动带 cookie）→ StrictAuth cookie 兜底 → 进入应用；SSE / WebSocket 同源同样自动带 cookie，无需 token 参数已有
Traefik 反代
mode: proxy		 外层认证Traefik forwardAuth 委托 Authelia /api/verify；未登录由 Authelia 302 门户；通过后 authResponseHeaders: [Remote-User] 注入身份头部署项
头换会话来源 IP ∈ trusted_proxies（traefik 容器网段）→ 读 username_header（配 Remote-User）→ 自动开户 → Set-Cookie: dockge_token → StrictAuth 放行已有
登录页按钮 ✦proxy 模式登录页「SSO 登录」= 整页加载 /（重走 Traefik → ProxyAuth 链）；原先 SPA 内跳转会重复失败的 boot()，形成登录页死循环已修
fail-closedtrusted_proxies 为空或来源不命中 → 一律 401（伪造头不可用）；配置见操作指南已有
本地密码
mode: jwt		 登录POST /v1/login（IP+账号 10 次/分钟滑动窗口限流）→ JWT 入 localStorage → Authorization: Bearer已有
2FA开启 TOTP 的账号返回 tokenRequired →（前端验证码步骤为 F4 目标，原型见 vision.html Screen A）目标
回调地址 ✦反代/TLS 部署下 OIDC redirect URI 改由 http.base_url 配置（如 https://dockge.example.com）；原先硬拼内网 host:port已修
